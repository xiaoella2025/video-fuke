# 视频复刻学员包与激活码 Skill

## 1. Skill 定位

这是视频复刻流程里的第二个 Skill。

它不负责整理 JSON 节点，不负责修改 `courseData.json`。它只在案例数据已经整理完成以后，继续处理学员交付相关事项：

1. 单案例学员包
2. 学员端启动方式
3. 机器码 / 设备码显示
4. 老师端生成激活码工具
5. README 学员说明
6. 最终视频放置路径
7. 最终打包前检查
8. 压缩包解压密码提醒

每次执行本 Skill 时，先确认案例数据是否已经完成。如果数据还没整理完，应提醒用户先执行“视频复刻案例整理 Skill”。

## 2. 和第一个 Skill 的区别

| Skill | 文档路径 | 负责内容 | 不负责内容 |
|---|---|---|---|
| 视频复刻案例整理 Skill | `docs/video-fuke-case-cleanup-skill.md` | 整理 `source.json` / `courseData.json`、清理模型字段、补输入图 / 输入视频、补场景视频链路、整理分镜链路、整理视频延长 / 补帧、输出数据自检报告 | 学员包、激活码、最终打包 |
| 视频复刻学员包与激活码 Skill | `docs/video-fuke-student-package-activation-skill.md` | 做单案例学员包、检查 `start.bat`、检查端口隔离、检查最终视频入口、启用机器码 / 激活码流程、检查老师端激活码工具、检查 README、最终打包前自检 | 修改 `courseData.json`、重新整理节点、改场景链路或分镜链路 |

不要把 Skill 2 的内容写进 Skill 1。

不要让 Skill 2 修改 `courseData.json`。

## 3. 启用词

用户说以下任意一句，都表示启用本 Skill：

1. 做学员包
2. 生成学员包
3. 做激活码
4. 配置激活码
5. 学员包授权
6. 复刻学员包
7. 打包复刻课程
8. 准备发给学员
9. 做课程交付包
10. 生成视频复刻学员包

推荐用户最常用的一句话是：

```text
做学员包 case-03
```

或者：

```text
配置激活码 case-03
```

## 4. 启动后先回复用户什么

当用户说“做学员包 case-03 / 配置激活码 case-03 / 准备发给学员”等启用词时，Codex 不要马上乱改文件，要先回复用户：

```text
视频复刻学员包与激活码 Skill 已启动。
我会先确认 case-03 的数据已经整理完成，再检查学员包、启动方式、最终视频、机器码 / 激活码流程和 README，最后输出打包前自检报告。
```

如果用户已经说了案例编号，例如 `case-03`，就直接使用这个编号，不要重复追问。如果用户没有说案例编号，先让用户确认目标 case。

然后告诉用户一共分 6 步：

### 第 1 步：确认案例数据已完成

- 检查 `course-data/case-03/courseData.json` 是否存在。
- 不修改 `courseData.json`。
- 如果数据还没整理完成，提醒用户先运行“视频复刻案例整理 Skill”。

### 第 2 步：生成或检查单案例学员包

- 学员包目录建议为 `packages/case-03-name`。
- 学员包只显示当前案例。
- 不显示其他案例。
- 不显示 `25cm`。
- 不要求学员安装 Git。
- `start.bat` 必须从学员包目录启动。

### 第 3 步：检查最终视频入口

- 预留最终视频路径。
- 推荐路径：

```text
packages/案例包名/web/assets/cases/case-03/preview/case-preview.mp4
```

- 如果最终视频不存在，不要编造。
- 明确告诉用户把 mp4 放到哪里。
- 如果最终视频已存在，要确认能播放。

### 第 4 步：配置机器码 / 激活码流程

- 学员打开后先显示机器码。
- 学员把机器码发给老师。
- 老师生成激活码。
- 学员输入激活码后进入课程。
- 不使用普通共享课程密码。
- 不使用 `qifeng-2026` 这类普通密码作为最终入口。

### 第 5 步：检查老师端生成激活码工具

- 老师端工具放在 `admin-tools` 或 `owner-tools`。
- 老师端工具不能进入学员包。
- 私钥不能进入学员包。
- 如果使用 HTML 工具，要支持目标 `courseId`。
- 例如 `case-03` 不能误用 `25cm` 的 `courseId`。
- 老师端工具应能输入学员机器码并输出激活码。
- 应提供复制激活码按钮或清晰复制方式。

### 第 6 步：最终打包前自检

- README 是否写清楚。
- `start.bat` 是否可用。
- 端口是否隔离。
- 课程是否只显示当前案例。
- 机器码 / 激活码是否可用。
- 最终视频是否存在，或路径提示是否清楚。
- 是否没有误改 `25cm`。
- 是否没有把私钥放进学员包。
- 是否没有把整个 Git 仓库打包进去。

## 5. 正式授权流程

正式学员授权流程必须是：

1. 老师把压缩包发给学员。
2. 压缩包可以由老师最后本地用 7-Zip 设置解压密码。
3. 学员用老师提供的解压密码解压。
4. 学员双击 `start.bat`。
5. 页面显示机器码 / 设备码。
6. 学员复制机器码发给老师。
7. 老师使用老师端工具生成激活码。
8. 学员输入激活码。
9. 激活成功后进入课程。
10. 换电脑需要重新生成机器码和激活码。

压缩包解压密码不是网页代码里的密码。

不要把解压密码写进 `activation.js`。

不要把普通课程密码当成最终授权方式。

## 6. 不要再用普通密码模式

正式学员包不要使用普通共享密码作为课程入口。

不要使用：

```text
qifeng-2026
```

不要让学员只输入一个普通课程密码就进入课程。

如果代码里为了兼容保留 `password` 分支，可以保留；但正式学员包的 `activation.config.js` 不应配置 `password` 字段。

正式学员包应走机器码 / 激活码流程。

## 7. 老师端私钥管理规则

1. 私钥只能放在老师端目录，例如 `admin-tools` 或 `owner-tools`。
2. 私钥不能放进 `packages/学员包`。
3. 私钥不能进入最终学员 zip。
4. 私钥不能提交到 GitHub。
5. `.gitignore` 应保护：
   - `admin-tools/private-key*`
   - `admin-tools/*.local.*`
   - `owner-tools/private-key*`
   - `owner-tools/*.local.*`
6. 如果旧老师端工具是 HTML 文件，不是 JSON，也可以复用。
7. 如果旧 HTML 工具里内置或引用私钥，应保持在老师端，不进学员包。
8. 一个私钥可以用于多个课程，但生成激活码时必须绑定不同 `courseId` 和 `deviceCode`。
9. 不要随便重新生成新密钥。
10. 如果重新生成密钥，必须提醒用户旧激活码可能失效。

## 8. 老师端 HTML 激活码工具规则

如果老师端使用 HTML 工具，例如：

```text
admin-tools/generate-license-qifeng.html
```

或类似工具，需要满足：

1. 页面标题能显示当前课程名称。
2. 默认 `courseId` 是当前案例，例如 `case-03`。
3. 不要默认用 `25cm` 给新案例生成激活码。
4. 支持粘贴学员机器码。
5. 支持导入或粘贴老师私钥 JWK。
6. 点击生成后输出激活码。
7. 提供复制激活码按钮。
8. 生成的激活码必须能被对应学员包验证。
9. 用错误 `courseId` 生成的激活码应不能激活当前案例。
10. 不要把老师端 HTML 工具打进学员包。

## 9. 学员端 activation.config.js 要求

学员包配置中需要确认：

1. `enabled` 应为 `true`。
2. `courseId` 应为当前案例，例如 `case-03`。
3. `devicePrefix` 应与当前案例匹配，例如 `QIFENG` 或 `CASE03`。
4. `publicKey` 应与老师端私钥配对。
5. 不应配置普通 `password` 字段。
6. `title` 应显示当前课程名称。
7. 学员端显示的机器码应绑定 `courseId`。
8. 验证激活码时必须检查：
   - `payload.courseId`
   - `payload.deviceCode`
   - 签名
   - `issuedAt` 或必要字段

## 10. README 必须写清楚

每个学员包 README 必须包含：

1. 如何解压。
2. 压缩包密码由老师提供。
3. 如何启动 `start.bat`。
4. 打开地址是什么。
5. 页面会显示机器码。
6. 如何复制机器码。
7. 机器码发给谁。
8. 老师返回激活码。
9. 如何输入激活码。
10. 激活失败怎么办。
11. 换电脑需要重新激活。
12. 不需要 Git。
13. 不需要命令行基础。
14. 所有内容本地运行，不上传云端。
15. 如果端口被占用怎么办。
16. 如果 Python 未安装怎么办。
17. 如何清除本机已激活状态。

README 不要写普通课程密码。

## 11. 最终视频规则

1. 最终视频推荐文件名：

```text
case-preview.mp4
```

2. 最终视频推荐路径：

```text
packages/学员包名/web/assets/cases/case-xx/preview/case-preview.mp4
```

3. 如果远程环境看不到 mp4，不要编造已包含。
4. 如果 mp4 在用户本地未提交，要明确告诉用户：
   - 本地能播放不代表远程能打进 zip。
   - 最终压缩前要确认 mp4 已在学员包目录里。
5. 如果不想把 mp4 提交到 Git，可以由用户本地把 mp4 放进学员包后再压缩。
6. 打包前必须确认最终视频是否存在。
7. 如果不存在，README 应有占位说明。

## 12. 最终打包规则

最终打包前必须确认：

1. 学员包只包含当前案例。
2. 学员包不包含 `25cm`。
3. 学员包不包含 `.git`。
4. 学员包不包含 `node_modules`。
5. 学员包不包含老师端私钥。
6. 学员包不包含 `admin-tools`。
7. 学员包不包含 `owner-tools`。
8. `start.bat` 可启动。
9. README 存在。
10. activation 机制可用。
11. 最终视频存在，或明确提示用户放置路径。
12. 最外层应该是一个文件夹，不要解压后散落一堆文件。

压缩包解压密码由用户最后本地用 7-Zip 设置，不由代码实现。

12. 是否去掉普通密码。
13. 老师端生成激活码工具路径。
14. 老师如何生成激活码。
15. 是否生成测试激活码；如果不能，缺少什么。
16. 私钥是否没有进入学员包。
17. README 是否写清楚。
18. 是否影响 `25cm`。

20. `git status` 是否干净。
21. commit 信息。
